Devloop command-line interface provides the following commands:


End-to-end pipelines:

* [devloop run](#devloop-run) - to build & deploy once
* [devloop dev](#devloop-dev) - to trigger the watch loop build & deploy workflow with cleanup on exit
* [devloop debug](#devloop-debug) - to run a pipeline in debug mode

Pipeline building blocks for CI/CD:

* [devloop build](#devloop-build) - to just build and tag your image(s)
* [devloop deploy](#devloop-deploy) - to deploy the given image(s)
* [devloop delete](#devloop-delete) - to cleanup the deployed artifacts
* [devloop render](#devloop-render) - build and tag images, and output templated Kubernetes manifests
* [devloop apply](#devloop-apply) - to apply hydrated manifests to a cluster

Getting started with a new project:

* [devloop init](#devloop-init) - to bootstrap Devloop config
* [devloop fix](#devloop-fix) - to upgrade from older devloop.yaml schema version to newer devloop.yaml schema version 

Other Commands:

* [devloop help](#devloop-help) - print help
* [devloop version](#devloop-version) - get Devloop version
* [devloop completion](#devloop-completion) - setup tab completion for the CLI
* [devloop config](#devloop-config) - manage context specific parameters
* [devloop credits](#devloop-credits) - export third party notices to given path (./devloop-credits by default)
* [devloop diagnose](#devloop-diagnose) - diagnostics of Devloop works in your project
* [devloop schema](#devloop-schema) - list and print json schemas used to validate devloop.yaml configuration


## Global flags

| Flag | Description |
|------- |---------------|
|`-h, --help`| Prints the HELP file for the current command.|
|`-v, --verbosity LOG-LEVEL` | Uses a specific log level. Available log levels are `info`, `warn`, `error`, `fatal`, `debug` and `trace`. Default value is `warn`.|


## Global environment variables

| Flag | Description |
|------- |---------------|
|`DEVLOOP_UPDATE_CHECK`|Enables checking for latest version of the Devloop binary. By default it's `true`. |

### devloop build

Build the artifacts

```


Examples:
  # Build all the artifacts
  devloop build

  # Build artifacts with a profile activated
  devloop build -p <profile>

  # Build artifacts whose image name contains <db>
  devloop build -b <db>

  # Quietly build artifacts and output the image names as json
  devloop build -q > build_result.json

  # Build the artifacts and then deploy them
  devloop build -q | devloop deploy --build-artifacts -

  # Print the final image names
  devloop build -q --dry-run

Options:
    --assume-yes=false:
	If true, devloop will skip yes/no confirmation from the user and default to yes

    --build-concurrency=-1:
	Number of concurrently running builds. Set to 0 to run all builds in parallel. Doesn't violate build order among dependencies.

    -b, --build-image=[]:
	Only build artifacts with image names that contain the given substring. Default is to build sources for all artifacts

    --cache-artifacts=true:
	Set to false to disable default caching of artifacts

    --cache-file='':
	Specify the location of the cache file (default $HOME/.devloop/cache)

    --check-cluster-node-platforms=false:
	When set to true, images are built for the target platforms matching the active kubernetes cluster node platforms. Enabled by default for `dev`, `debug` and `run`

    -c, --config='':
	File for global configurations (defaults to $HOME/.devloop/config)

    -d, --default-repo='':
	Default repository value (overrides global config)

    --detect-minikube=true:
	Use heuristics to detect a minikube cluster

    --disable-multi-platform-build=false:
	When set to true, forces only single platform image builds even when multiple target platforms are specified. Enabled by default for `dev` and `debug` modes, to keep dev-loop fast

    --dry-run=false:
	Don't build images, just compute the tag for each artifact.

    --file-output='':
	Filename to write build images to

    -f, --filename='devloop.yaml':
	Path or URL to the Devloop config file

    --insecure-registry=[]:
	Target registries for built images which are not secure

    --kube-context='':
	Deploy to this Kubernetes context

    --kubeconfig='':
	Path to the kubeconfig file to use for CLI requests.

    -m, --module=[]:
	Filter Devloop configs to only the provided named modules

    --mute-logs=[]:
	mute logs for specified stages in pipeline (build, deploy, status-check, none, all)

    -n, --namespace='':
	Runs deployments in the specified namespace. When used with 'render' command, renders manifests contain the namespace

    -o, --output={{json .}}:
	Used in conjunction with --quiet flag. Format output with go-template. For full struct documentation, see https://godoc.org/github.com/lucky-tools/devloop/cmd/devloop/app/flags#BuildOutput

    --platform=[]:
	The platform to target for the build artifacts

    -p, --profile=[]:
	Activate profiles by name (prefixed with `-` to disable a profile)

    --profile-auto-activation=true:
	Set to false to disable profile auto activation

    --propagate-profiles=true:
	Setting '--propagate-profiles=false' disables propagating profiles set by the '--profile' flag across config dependencies. This mean that only profiles defined directly in the target 'devloop.yaml' file are activated.

    --push=:
	Push the built images to the specified image repository.

    -q, --quiet=false:
	Suppress the build output and print image built on success. See --output to format output.

    --remote-cache-dir='':
	Specify the location of the remote cache (default $HOME/.devloop/remote-cache)

    --rpc-http-port=:
	tcp port to expose the Devloop API over HTTP REST

    --rpc-port=:
	tcp port to expose the Devloop API over gRPC

    --skip-tests=false:
	Whether to skip the tests after building

    --sync-remote-cache='always':
	Controls how Devloop manages the remote config cache (see `remote-cache-dir`). One of `always` (default), `missing`, or `never`. `always` syncs remote repositories to latest on access. `missing` only clones remote repositories if they do not exist locally. `never` means the user takes responsibility for updating remote repositories.

    -t, --tag='':
	The optional custom tag to use for images which overrides the current Tagger configuration

    --toot=false:
	Emit a terminal beep after the deploy is complete

    --wait-for-connection=false:
	Blocks ending execution of devloop until the /v2/events gRPC/HTTP endpoint is hit
```
